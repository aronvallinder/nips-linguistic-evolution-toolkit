# API-equivalence audit: history + external provider behaviour (2026-09-04)

## Headline

The three models did NOT run with matching settings. Since 2026-04-29 the repo routes `openai/*`, `anthropic/*` and `google/*` slugs to the direct vendor APIs whenever a key is present (`LLM_PROVIDER=auto`), and each direct path silently applies its own sampling and reasoning policy. Empirically, in the run data on disk:

| Model / path | Temperature sent | Reasoning / thinking | Output cap | Evidence |
|---|---|---|---|---|
| Claude Sonnet 4.5, direct Anthropic (Aug-12 confirmatory, Jul-22 v2 noise, Jul-20 mem3) | 0.8 | OFF (no `thinking` param) | 4096 (`ANTHROPIC_MAX_TOKENS`), was 1024 before 2026-07-20 | `src/utils.py:_call_anthropic`; runs show 0 % messages with reasoning text |
| Claude Sonnet 4.5, OpenRouter (Jun directive_normative, Jul-17 plain memprimary game + game_myth, noise2i dyads) | 0.8 | ON, `reasoning.effort=medium` → Anthropic extended thinking | provider default | `src/utils.py:_call_openai_compatible` sends `extra_body.reasoning`; runs show 79–100 % messages with a distinct thinking block, 138–382 reasoning tokens where OpenRouter reported them |
| GPT-5 Nano, direct OpenAI (all Aug-21..24 GPT cells) | NOT sent (OpenAI fixes 1.0) | `reasoning_effort=minimal` (repo default) | none | `_supports_custom_temperature`, `_direct_openai_reasoning_effort`; runs: mean 16–123 output tokens, 0 reasoning tokens |
| GPT-5 Nano, OpenRouter (Jul-01 source runs) | 0.8 sent, OpenRouter drops it (not in `supported_parameters`) | OpenAI default effort (medium; reasoning summaries returned) | none | run: 7050 output tokens for one myth call, reasoning summaries stored |
| Gemini 3.7 Flash, direct Google (Aug-23/24) | NOT sent (model ignores it) | `thinkingLevel=medium` (explicit, = Google default) | none | metadata `temperature_sent:false, thinking_level:medium`; ~120–130 thinking tokens/call |
| Gemini 3.1 Flash-Lite, direct Google (Aug-21/22) | 0.8 | not set → provider default; 0 thinking tokens reported | none | metadata `llm_provider:google`, no `thinking_level` key |

So: Claude ran at T=0.8 with thinking off (direct) or on (OpenRouter, depending on credit balance that week); GPT-5 Nano ran at T=1.0 with essentially no reasoning; Gemini 3.7 ran with medium thinking and no temperature control. Message *roles* are mapped equivalently on all three paths (system → `system` / `system_instruction`; assistant → `model` for Gemini). The inequivalence is in sampling and reasoning settings, not roles.

One within-Claude confound: the plain 8-agent memory-primary triplet plotted by `scripts/memprimary_taskorder_boxplot.py` mixes providers. `game` and `game_myth` (Jul-17) were rerun via OpenRouter after the Anthropic balance ran dry (researchlog 2026-07-17 entry, line 1085) and have thinking ON (79 % / 96 % of calls carry a thinking block); the `myth_game` leg (`sonnet45_8agent_myth_directive_history3_anon_memprimary_r10_n5`) ran direct with thinking OFF (0 %). The informed-noise v2 triplet (Jul-22) and the Aug-12 corrected_v2 runs are consistently direct/thinking-off, so they are not affected.

Documentation contradictions:
- `CLAUDE.md` says `src/simulation.py` "uses `OPENROUTER_API_KEY` to instantiate the OpenAI client (pointed at openrouter.ai)". Actual: `create_llm_client(model)` picks the provider by slug and key presence (`src/utils.py:170-222`); `simulation.py:379`.
- `README.md:18` calls direct keys "optional" without saying their mere presence changes the provider under the default mode.
- `.env.example` documents `LLM_PROVIDER`, `OPENROUTER_MAX_TOKENS`, `OPENROUTER_REASONING_EFFORT`, `ANTHROPIC_MAX_TOKENS` but not `OPENAI_REASONING_EFFORT`, `GEMINI_THINKING_LEVEL`, `GEMINI_REQUEST_TIMEOUT_SECONDS`, or `LLM_DIRECT_MODEL_<SLUG>` overrides, all of which affect experimental conditions.
- `docs/verified-facts.md` correctly records the auto→direct routing and the OpenRouter fallback, but does not record that the fallback turns Claude extended thinking on.
- The Aug-21..24 protocol docs say "temperature 0.8 where the provider accepts it" and "direct Google API and medium thinking"; they do not state that GPT ran at minimal reasoning or that Claude ran with thinking off, so a reader of the protocols would not see the asymmetry.

## Ranked risks

1. **Reasoning depth differs by model and by provider path (highest).** Claude: thinking OFF on direct, medium-effort thinking ON via OpenRouter. GPT-5 Nano: `minimal` on direct (Aug cross-model cells), vendor default via OpenRouter (Jul). Gemini 3.7: medium. A "cross-model" comparison therefore compares a non-thinking Claude with a minimally-reasoning GPT and a medium-thinking Gemini. Evidence: `src/utils.py` lines 379-405, 531-536, 615-635; run metadata and reasoning-token counts above. GPT-5 Nano's "anomalous behaviour" (meeting 2026-09-01) is consistent with `minimal` effort, which OpenAI positions as near-zero reasoning; nobody chose that setting for scientific reasons (commit 83654c20 message: "Use minimal reasoning for direct GPT-5 calls").
2. **Temperature is not a shared condition.** 0.8 on Claude and Gemini 3.1 Flash-Lite; fixed 1.0 on GPT-5 Nano; ignored on Gemini 3.7. Protocol docs say "0.8 where the provider accepts it" but analyses do not stratify on it.
3. **Provider switches mid-study changed Claude's condition without a config change.** Credit exhaustion on 2026-07-17 and again the week of the lineage A/B (researchlog 1015, 1085) flipped Claude from direct (no thinking) to OpenRouter (thinking). The plain memprimary triplet in `scripts/memprimary_taskorder_boxplot.py` mixes both (game, game_myth thinking-on; myth_game thinking-off). Any Myth→Game vs Game→Myth claim from that triplet is confounded.
4. **Runs before 2026-08-12 have no provider metadata.** `llm_runtime_metadata` only exists from fce6f1da; older runs must be classified by the presence of a distinct `reasoning` field (OpenRouter Claude) or by researchlog notes.
5. **Refusal/empty-response retry exists only on the Anthropic path.** OpenAI and Gemini empty responses abort the run; a `minimal`-effort or cap-exhausted reply can be empty.
6. **No output cap on GPT/Gemini direct paths; 4096 on Claude.** Claude replies that exceed 4096 tokens are truncated and fail JSON extraction; GPT/Gemini are unbounded. Asymmetric failure mode, though at `minimal` GPT outputs are tiny.
7. **OpenRouter reasoning-token accounting is inconsistent.** Jul-17 OpenRouter Claude runs carry thinking text but `reasoning_tokens=0`; Jun runs report 138–382. Cost and "reasoning length" analyses that use `usage.reasoning_tokens` undercount.
8. **Docs mislead.** CLAUDE.md/README still describe a single OpenRouter client; `.env.example` omits the GPT/Gemini reasoning knobs. The PI's belief that everything goes through OpenRouter with identical parameters comes from these docs.

## Not verified / limits

- gpt-5-nano's vendor default `reasoning_effort` (openai.com launch post returned 403; the current guide names only gpt-5.5). Inferred medium from output-token volumes.
- What `max_tokens` OpenRouter forwards to Anthropic when the client sends none (Anthropic requires it). Community reports suggest a high default (~65k) but no OpenRouter doc states it; this determines the thinking budget that OpenRouter-era Claude runs actually had.
- Gemini 3.1 Flash-Lite's default thinking behaviour when `thinkingConfig` is absent (runs report 0 `thoughtsTokenCount`, consistent with thinking off, but not confirmed in docs).
- Whether OpenRouter's Gemini adapter maps the first system message to `systemInstruction` is from a third-party issue tracker, not OpenRouter docs.
- The Aug-12 `corrected_v2_confirmatory` Claude run files are not on this machine (only the `v2_smoke_20260812` mirror), so their thinking-off status is inferred from the launcher (`LLM_PROVIDER=anthropic`) and the smoke files, not from the confirmatory JSONs themselves.
- No repo file was modified; all data checks were read-only on `data/json/` and `nlet-hf-data/`.
