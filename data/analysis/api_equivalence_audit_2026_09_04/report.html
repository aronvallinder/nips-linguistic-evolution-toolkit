Are the Claude, GPT and Gemini API calls equivalent?

Team-meeting action item from 2026-09-01. Three Claude agents (code path, run data, history and provider docs) and one independent Codex agent audited the repo and every saved run. All four reached the same answer.

No. The runs on the meeting slides did not go through OpenRouter, and the three models did not share sampling settings.

The 270-run cross-model defector set from 2026-08-25 sent each model to its own vendor API directly. Claude played at temperature 0.8 with no thinking. GPT-5 Nano played at the vendor's fixed temperature with reasoning effort set to "minimal", which is near zero. Gemini 3.7 Flash played with medium thinking and no temperature control. Message roles and the system prompt are handled equivalently on all three paths, so this is not a role-format bug. It is a settings inequivalence plus one large format confound.

Findings, ranked by how likely each is to explain the cross-model differences

  1. Three vendors, three sampling regimes. The comparison pits a non-thinking Claude against a barely-reasoning GPT and a medium-thinking Gemini.

    Nobody chose "minimal" for GPT-5 Nano on scientific grounds. It is the code default for direct OpenAI calls, added in commit 83654c20 on 2026-04-29, and the August launch scripts left it unset. GPT-5 Nano's "anomalous" behaviour in the meeting is consistent with a model that does almost no reasoning. Temperature is not a shared condition either, even though every protocol doc says 0.8.

    Test: rerun one GPT-5 Nano cell with OPENAI_REASONING_EFFORT=medium and compare against the existing minimal-effort cell.

  2. Claude re-reads its own deliberation every round. The other two only see their past numbers.

    The validator accepts any reply that contains a quoted send or return key, and the whole accepted reply is stored as the next assistant message. Under memory-primary mode Claude therefore carries several paragraphs of its own strategic reasoning forward in its 3-round window, while GPT and Gemini carry bare JSON. This is a format-driven treatment difference that could produce "Claude degrades with defectors" on its own.

    Test: rerun a Claude cell with a prompt that requires JSON-only replies, or strip prose from stored assistant messages, and see whether the defector effect survives.

  3. Both Claude and GPT-5 Nano have run under two different regimes across the project, so older and newer results are not directly comparable.

    OpenRouter-era Claude runs (Arabella's five sets, Ivar's baseline, v1, v2, v3, myth_causal and sonnet45_8agent sets, ~1,100 runs) had extended thinking switched on, because the OpenRouter path sends reasoning effort medium by default. Direct-Anthropic runs (defector set, v4, phase 2 to 7, memtest, mem3) had none. GPT-5 Nano used a median of about 1,000 reasoning tokens per decision via OpenRouter and zero via direct OpenAI.

    Test: split any pooled Claude or GPT analysis by the reasoning signature (reasoning text present vs absent) before trusting it.

  4. Some conditions mix regimes inside a single comparison.

    The plain 8-agent memory-primary triplet plotted by scripts/memprimary_taskorder_boxplot.py has game and game_myth via OpenRouter (thinking on, after the Anthropic balance ran dry on 2026-07-17) and myth_game direct (thinking off). The washout_20round set and noise v2 also contain both regimes. Any Myth→Game vs Game→Myth claim drawn from that triplet is confounded. The informed-noise v2 triplet from 2026-07-22 and the 2026-08-12 confirmatory runs are consistently direct and unaffected.

  5. GPT-5 Nano confuses the two tasks: in 39 of 90 two-task runs it answered a myth prompt with a game decision.

    93 myth calls were rejected and retried with a correction suffix. Claude and Gemini had zero. The validator that catches this was added on 2026-08-25, so older GPT-5 Nano two-task runs may contain unflagged game JSON stored as myths.

    Test: regex older GPT-5 Nano myth fields for "send" or "return".

  6. Model-dependent failure rates filter the sample rather than defaulting values.

    A decision that fails validation is retried once, then the run dies and is excluded from the shared data. Claude had 18 such rejections in 15 runs (long analyses that never emitted the JSON line), the others none. Not large here, but it is a survivorship channel, and no finish_reason is ever stored so truncation can only be inferred from token counts.

What is not a bug

Verified equivalent

  • Message roles, system-prompt placement, seed injection and memory truncation are identical across providers (src/utils.py:270-316).
  • No silent parse default. Missing keys raise, retry once, then kill the run. The one historical default (return 0 when nothing was received) is benign.
  • No truncation and no empty replies in any completed slide-set run.
  • Model aliasing never bit: every metadata-bearing run resolved to the expected native model id.
  • Gemini's ceiling-lock is not a provider artefact. It maxes out under OpenRouter and direct, with and without visible thinking.

Cannot be verified from the repo

  • The exact code that produced the defector set: commit 58d15e24 is on no remote.
  • The reasoning effort actually used on any direct OpenAI run; it is never written to metadata.
  • Provider of the ~1,065 no-thinking Claude runs before 2026-08-25; direct Anthropic is likely but unproven.
  • Whether OpenRouter forwarded temperature 0.8 to GPT-5 Nano in the OpenRouter era. Its model card lists no temperature support, so it was most likely dropped.

How it happened

  • 2026-04-21Ivar's original code: one OpenRouter client for everything, temperature 0.8 always sent, medium reasoning for Claude and Gemini slugs, none for OpenAI slugs. Even then the models were not parameter-identical.
  • 2026-04-29Aron adds direct OpenAI, Anthropic and Gemini routing. auto mode prefers a direct vendor whenever its key is present. GPT-5 gets temperature dropped and reasoning effort "minimal"; Anthropic gets a 1024-token cap and no thinking.
  • 2026-05-11Meeting notes say discrepant results were "likely due to new API calls not allowing the same settings" and that the team would revert to the original code. No revert was ever committed.
  • 2026-07-17Anthropic balance runs dry; Ivar reruns via LLM_PROVIDER=openrouter, which silently turns Claude thinking on. Cap raised to 4096 after truncation killed two runs.
  • 2026-08-12Provider fields first written to run_metadata. Everything earlier carries no provenance.
  • 2026-08-21Cross-model screens launched with LLM_PROVIDER=direct, GPT effort unset (minimal), Gemini thinking medium.
  • 2026-08-25All of it merged to shared main. CLAUDE.md and README still describe a single OpenRouter client.

Recommended next steps

  • Pick one regime and pin it. Either all three via OpenRouter with an explicit OPENROUTER_REASONING_EFFORT, or all three direct with matched effort levels. Set it in the launch script, not in a per-machine .env.
  • Record what was sent. Add the effective reasoning effort, whether temperature was sent, and the response finish_reason to run_metadata and per-call usage.
  • Control the prose confound. Either require JSON-only decisions for all models or store only the extracted decision in memory. Rerun one Claude defector cell each way.
  • Rerun the GPT-5 Nano slide cells at medium effort before drawing any conclusion about GPT beating Claude on collective returns.
  • Re-plot the memory-primary triplet from consistently-routed runs only, or drop it.
  • Fix the docs. CLAUDE.md and README describe a single OpenRouter client; .env.example omits OPENAI_REASONING_EFFORT and GEMINI_THINKING_LEVEL; docs/verified-facts.md:9 cites a stale line number.
